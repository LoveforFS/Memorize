# 没有 Mac 怎么把项目做完：环境判定与推进方案

> 适用：Memorize / day8（SwiftUI + XCTest + XCUITest，iOS 16.0 部署目标）
> 检测时间：2026-11-09 16:38　检测机器：XINLIANCHUQING\22320

## 一、先说清"Mac"是什么

- **Mac** 是苹果公司生产的个人电脑整机（MacBook / Mac mini / iMac / Mac Studio）。
- 它跑的操作系统叫 **macOS**（基于 Unix，和 Linux 同源但不同分支）。
- 对本项目而言，"Mac"具体指三样东西，缺一不可：
  1. **macOS 系统** —— Xcode 的运行前提；
  2. **Xcode** —— 苹果官方 IDE，内含 `xcodebuild`、iOS SDK、Interface Builder；
  3. **iOS 模拟器** —— 基于 macOS 的虚拟设备，用来跑 XCUITest 和录屏。

为什么绕不开：**Xcode 和 iOS 模拟器只有 macOS 版本**。Windows 上的 Swift 只能编译命令行程序（还得额外装工具链），无法链接 UIKit/SwiftUI 的 iOS 框架，也没有模拟器。这不属于"装个插件就能解决"的范畴，是平台授权的硬边界——按苹果许可，macOS 也只能运行在 Apple 硬件上。

**结论（分开说，不要混为一谈）**：

- **原生运行：不具备**。不能 `xcodebuild`、不能跑 iOS 模拟器、不能录屏 → P0-1、P0-2 在本机**永久无法完成**，不是配置问题。
- **代码交付与等价验证：已具备且已完成**。132 条等价用例 100% 通过、Xcode 工程结构自检通过、验收脚本就绪 → 项目"做完了"，缺的是"在苹果设备上被证明"。

## 四、我建议的组合：C + A/B

1. **先用 C 拿 P0-1 的原生证据**（零成本、可重复、可写进答辩"我们在 CI 上跑了原生 132 条"）；
2. **再用 A 或 B 录 P0-2 的两段视频**（必须有人手点"再来一局"，CI 做不到）；
3. 两条证据合起来，R-03 与 R-03a 才能都改成"已完成"。

配套的 CI 配置我已经写好：`.github/workflows/macos-native-test.yml`（在项目根目录）。它做四件事：打印环境 → 自动挑一个可用 iPhone 模拟器 → 先跑等价回归（Python 132 条）→ 再跑原生 `xcodebuild test` 并上传 `TestResults.xcresult` 与日志。

## 五、路线 C 的具体操作（5 步，不涉及本地 git 提交）

> 注意：以下步骤需要你**自己**在 GitHub 上建仓库并推送。按你的要求，我这里不执行任何 `git add/commit/push`。

1. 在 GitHub 新建一个仓库（Public 最省事，macOS 分钟免费）；
2. 由你在本地推送当前代码（这一步会包含提交动作，等你说要做时再执行；也可用 GitHub 网页上传 zip 解压）；
3. 打开仓库的 **Actions** 页，选中「macOS 原生验收」工作流，点 **Run workflow**；
4. 约 5–10 分钟后看结果：绿勾 = 原生通过；红叉 = 展开日志看第一个 `error:`；
5. 在 **Artifacts** 下载 `memorize-native-evidence`，里面有 `xcodebuild-test.log` 和 `TestResults.xcresult`，把它们放进 `Test/native_acceptance/evidence/<日期>/`，然后按 `Test/证据回填清单-原生验收.md` 回填 4 处。

如果 CI 报的是"找不到 iPhone 15"，说明 runner 的 Xcode 版本变了——工作流里已做降级：低于 15 会自动换用其他可用 iPhone 机型，并把实际使用的机型写进日志。

## 六、路线 A / B 的操作要点（录屏那天）

1. 先把 `Test/WorkBuddy-Delivery/`（91 文件交付包）整体拷过去，包根即工程根，不用改路径；
2. 跑 `bash verify_macos_env.sh ./`，`FAIL=0` 再继续；
3. 跑 `bash native_acceptance/run_native_acceptance.sh`，拿到原生证据（顺便验证 P0-1）；
4. 按 `录屏拍摄清单.md` 录两段，重点是镜头 8「倒计时归零 → 时间到 → 再来一局」一镜到底；
5. 录完把 mp4 拷回本项目 `day8/录屏/`（该目录已被 `.gitignore` 排除，不会误入版本库）。

## 八、如果最终确实拿不到 Mac

1. 报告里明确写"原生未验证，等价已验证 132/132"，并附本方案说明为何受环境限制；
2. 展示验收脚本 + CI 配置，证明"不是做不到，是缺设备"；

**绝对不要**：伪造 `.xcresult`、伪造终端截图、或用 Windows 等价结果冒充原生结果。
