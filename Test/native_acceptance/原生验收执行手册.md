> 适用版本：day8 / D8 整合交付版（2026-11-09）
> 目标：在 macOS 上把「原生编译 + 132 条全量测试」跑通，并自动生成 P1-1 所需的全部证据字段。
> 执行者只需一台 Mac，不需要懂项目内部实现；全部命令可复制执行。

## 二、前置条件（缺一不可）

1. macOS 13.5+（推荐 14+），磁盘剩余 ≥ 20 GB；
2. Xcode 15.0+，且已执行过一次 `sudo xcodebuild -license accept`，并安装 iOS 平台组件；
3. 至少一个 iOS 16/17 模拟器 runtime，且存在 `iPhone 15` 设备（缺失时脚本自动回退到其他 iPhone，并打印 WARN）；
4. 项目目录可读，`day8/Memorize.xcodeproj` 存在。

一次性自检（可选，30 秒）：

```bash
cd <项目根>/Test
bash verify_macos_env.sh ../day8
```

`FAIL=0` 才算环境就绪；若报 SDK 缺失，执行 `xcodebuild -downloadPlatform iOS` 后重试。

## 三、一键执行（推荐）

```bash
cd <项目根>/Test/native_acceptance
bash run_native_acceptance.sh
```

脚本会按 `../../day8` → `../day8` → `..` → 当前目录 的顺序自动探测工程，通常不需要传参；若目录结构特殊，再显式传 `bash run_native_acceptance.sh /路径/day8`。

预期终端结构：

1. 环境前置 3 项 `[OK]`，并打印 macOS / Xcode / Swift / iOS SDK 版本；
2. `[1/3] xcodebuild -list`：4 项 `[OK]`（3 个 Target + 共享 Scheme）；
3. `[2/3] xcodebuild test`：逐条用例滚动输出，UI 用例较慢，整体约 3–8 分钟，**不要中断**；
4. `[3/3] 结果解析`：
   ```
   汇总行：Executed 132 tests, with 0 failures, 0 skipped
   状态标记：TEST SUCCEEDED（xcodebuild 退出码 0，耗时 xxxs）
   识别到 2 个测试 bundle
   判定：通过
   ```
5. 生成 `Test/native_acceptance/evidence/<时间戳>/native-evidence.md`，其第五节含 4 段可直接粘贴的回填片段。

退出码：`0` 通过 / `1` 判定未通过 / `2` 环境或工程前置不满足。

### 指定设备或工程根

```bash
DEVICE_NAME="iPhone 15 Pro" bash run_native_acceptance.sh
bash run_native_acceptance.sh /Users/xxx/WorkBuddy-Delivery   # 直接对交付包验收
```

### 不用脚本的手工路径（等价，便于交叉核对）

```bash
cd <项目根>/day8
xcodebuild -list -project Memorize.xcodeproj
xcodebuild test -project Memorize.xcodeproj -scheme Memorize \
  -destination 'platform=iOS Simulator,name=iPhone 15' \

```

判定：末尾出现 `** TEST SUCCEEDED **`，且最后一段 `Executed 132 tests, with 0 failures (0 unexpected)`。

## 四、不通过时的排查顺序（按此顺序，逐条修完再重跑）

| 序号 | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | `error: unable to find utility "xcodebuild"` / `requires Xcode` | 只装了 Command Line Tools | `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer` |
| 2 | `Signing for "Memorize" requires a development team` | 自动签名缺 Team | Xcode → Target → Signing & Capabilities 选个人 Team；模拟器测试也可在 Build Settings 将 `CODE_SIGNING_ALLOWED` 设为 NO 仅用于本地验证（**不得提交该改动**） |
| 3 | 编译报错（类型/API） | Swift 源码与 SDK 不匹配 | 逐条按报错修，**修完必须重跑 `python day8/WinTestHarness/run_tests.py` 保持 132/132** |
| 4 | `Unable to boot device` / 设备不存在 | runtime 缺失 | `xcodebuild -downloadPlatform iOS`，或 `DEVICE_NAME` 换已存在机型 |
| 5 | UI 用例失败且报"找不到元素" | 可访问性标识未生效或元素未出现 | 对照 README「7 个可访问性标识」；先在 Xcode 里手动跑单条 `-only-testing:MemorizeUITests/GameFlowUITests/testMainScreenShowsCoreElements` 看现场 |
| 6 | 倒计时/动画类用例偶发失败 | 时序竞态（模拟器负载高） | 先重跑单套件 3 次；若稳定复现才改代码，且必须保留断言强度并补边界用例 |
| 7 | `resultBundlePath ... already exists` | 上次残留 | 换时间戳目录（脚本已自动按时间戳建目录，手工路径需自行改名） |
| 8 | `Executed 124 tests`（只有单元） | UI Target 未纳入 Scheme | 检查 `Memorize.xcscheme` 的 TestAction 是否含 MemorizeUITests；必要时 `python Test/gen_xcodeproj.py` 重建 |

## 五、跑通之后立刻接 P0-2（录屏）

1. 保持模拟器与构建产物不动，按 `day8/录屏拍摄清单.md` 录制；
2. 必录片段：倒计时归零 → "时间到！"弹窗 + 本局得分 → 点击"再来一局" → 弹窗关闭、得分归零、重新发牌、倒计时重启（**一镜到底**）；
3. 产出 `Memorize-演示-YYYYMMDD.mp4`（5–6 分钟）与 `Memorize-超时流程-YYYYMMDD.mp4`（60–90 秒），1080p/30fps/H.264；
4. **禁止**使用临时 10 秒倒计时构建录正式片。

## 六、常见坑

- 证据目录在 `Test/native_acceptance/evidence/`，**不要**放进 `day8/`，否则 `check_project.py` 的「day8 根目录无多余文件」会 FAIL；
- `-derivedDataPath` 已指向 `$TMPDIR`，不会污染仓库；若要复用增量构建可自行固定一个路径；
- 脚本每次运行都新建时间戳目录，历史证据不会被覆盖；
- 判定为"未通过"时，脚本仍会生成 `native-evidence.md`，但其中数字不得当作通过证据引用。

## 七、已知限制（第一次在真机 Mac 上跑时重点看这里）

1. **输出格式假设**：脚本按 Xcode 15 的 `Executed N tests, with M failures` 措辞解析。若 Xcode 16/26 改了措辞，会出现"未在日志中找到 Executed 汇总行"，此时以日志末尾的 `** TEST SUCCEEDED **` 与 Xcode Test Navigator 计数为准，并手工填写证据；
2. **UI 测试耗时**：8 条 XCUITest 在首次运行可能需 5–10 分钟（模拟器冷启动），不要提前中断；
3. **多 bundle 解析**：本工程固定 2 个 bundle（MemorizeTests 124 + MemorizeUITests 8）。若后续拆包，需同步修改 `parse_log` 的 bundle 匹配规则；
4. **自检可随时跑**：`bash run_native_acceptance.sh --selftest` 不需要 Xcode，改动脚本后先自检再上 Mac。
