## 二、网络层：本次唯一需要动全局配置的地方

### 现象

Watt Toolkit 的加速方式是把 GitHub 相关域名在 `hosts` 里全部指向 `127.0.0.1`，
由本地反向代理在 443 端口接管 TLS。因此 git 直连时面对的是**代理的自签根证书**，
两个后端各自报错：

| 后端 | 报错 | 原因 |
| --- | --- | --- |
| schannel（默认） | `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)` | 自签证书没有 CRL/OCSP 分发点，无法完成吊销检查 |
| openssl | `unable to get local issuer certificate (20)` | git 自带 `ca-bundle.crt` 不含 SteamTools 根证书 |

### 处理

SteamTools 根证书（`CN=SteamTools Certificate`，`O=BeyondDimension`）本来就已经装在
Windows 受信任根存储里，所以**不需要降低任何校验强度**。正确做法是把它并入 git 的 CA 包：

1. 从 `Cert:\LocalMachine\Root` 导出该证书为 PEM；
2. 与 git 官方 CA 包拼接成独立文件，不动 `Program Files`；
3. 让 git 走 openssl 后端并指向这个合并包。

合并产物：`C:\Users\22320\.workbuddy\certs\ca-bundle-with-steamtools.crt`
（151 张证书 = git 官方 CA 全部 + SteamTools 根证书）

写入的全局配置：

```bash
git config --global http.sslBackend openssl
git config --global http.sslCAInfo "C:/Users/22320/.workbuddy/certs/ca-bundle-with-steamtools.crt"
```

验证：`git ls-remote https://github.com/octocat/Hello-World.git` 返回 0，证书验证全程开启。

### 明确没有采用的做法

没有使用 `http.sslVerify=false`。那样虽然也能推上去，但等于对所有 HTTPS 仓库关闭
证书校验，中间人可任意伪造，是把「网络能通」换成了「安全为零」，不可接受。

### 回滚

```bash
git config --global --unset http.sslBackend
git config --global --unset http.sslCAInfo
```

删除 `ca-bundle-with-steamtools.crt` 即可。回滚后会恢复 schannel 默认行为，
届时若仍开着 Watt Toolkit，git 会重新报 `CRYPT_E_NO_REVOCATION_CHECK`。

### 注意事项

- 该配置是**全局**的，会影响本机所有 git 仓库。因合并包包含 git 官方全部 CA，
  对非 GitHub 仓库同样成立，不会造成额外故障。
- Watt Toolkit 升级或重装后根证书可能更换，届时报 issuer 错误就重新导出一遍。
- 本会话 shell 中注入的 `https_proxy=http://127.0.0.1:58394` 会覆盖 hosts 指向，
  执行 git 命令时需先 `unset`（本记录中所有命令均已这样处理）。用户手动开终端不受影响。
