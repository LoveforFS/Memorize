## 四、问题清单

### R-01（P1，功能缺陷）倒计时超时后无法重开

- **证据**：
  - [GameView.swift](../day8/Memorize/Views/GameView.swift#L32-L43)：结算弹窗仅由 `isGameOver` 触发；
  - [GameView.swift](../day8/Memorize/Views/GameView.swift#L173-L175)：超时提示“点击「再来一局」重新开始”；
  - 全项目 `didTimeOut` 只出现在 ViewModel 与测试中，视图层未观察。
- **影响**：超时后 `isInteractionLocked = true`，卡片、主题栏、环形点击均被锁定，界面无任何可恢复入口；第 7 步演示（超时锁定）会直接卡死，只能杀进程。
- **建议修复**：统一结算弹窗，同时监听 `isGameOver` 与 `didTimeOut`，标题按状态显示“全部配对成功！”或“时间到！”，按钮仍为“再来一局”。
- **已提供补丁**：[Test/fix/GameView.swift](fix/GameView.swift)、[Test/fix/GameView.diff](fix/GameView.diff)、[应用说明](fix/README.md)。
- **当前状态**：复核后已按确认合入 `day8/Memorize/Views/GameView.swift`，并重跑等价回归 132/132 通过；macOS 编译与 UI 用例验证待执行。

### R-02（P2，交付风险）仓库不包含 Xcode 工程文件

- **证据**：全仓库无 `.xcodeproj`；README §4.2 要求新建工程并手动挂载源码。
- **影响**：验收方无法“双击打开即可运行”，首次构建依赖人工操作，存在挂载遗漏（如测试目标未加入、模块名不一致）导致 `@testable import Memorize` 失败的风险。
- **建议**：在具备 macOS 的机器上生成一次 `.xcodeproj` 并入库，或提供 XcodeGen 的 `project.yml`；同时在 README 增加“工程生成后可执行 `xcodebuild -list` 自检”的步骤。

### R-03（P2，验证风险）132 条为等价镜像结果，非原生 XCTest

- **证据**：README §5.3 明确“逻辑等价 / UI 状态投影级等价”；`test_results.json` 由 Python 执行器生成。
- **影响**：无法排除 Swift 编译错误、SwiftUI 布局差异、XCUITest 元素定位差异；答辩时若被追问“是否真机跑过”，当前无实机证据。
- **建议**：按 README §5.2 在 macOS 执行 `xcodebuild test`，保留日志与截图；完成真机录屏。

### R-04（P3，文档一致性）D4 与 D5 日报日期重复

- **证据**：docx 解析结果 D4、D5 均为“2026 年 11 月 5 日”。
- **影响**：日报时间线出现重复日期，影响归档严谨性；不影响代码与测试。
- **建议**：历史日报不建议改档；可在最终汇总材料中说明“D4 与 D5 同日完成”，或将 D5 报告日期修正后单独归档。

### R-05（P3，兼容性）`onChange(of:)` 单参数写法在 iOS 17 SDK 下已弃用

- **证据**：`GameView` 中 `onChange(of: ...) { newValue in }` 为 iOS 16 风格；Xcode 15 编译会产生弃用告警。
- **影响**：当前部署目标 iOS 16 可正常运行；升级到 iOS 17 双参数签名时需同步修改，否则只是告警。
- **建议**：若后续升级最低版本，统一改为 `onChange(of:) { oldValue, newValue in }`。

### R-06（P3，文档可移植性）README 的 Windows 命令写死解释器绝对路径

- **证据**：命令为 `D:\miniconda3\python.exe ...`。
- **影响**：换机器后命令不可直接复制；脚本本身无第三方依赖，任意 Python 3 均可运行。
- **建议**：README 改为 `python WinTestHarness/run_tests.py`，并注明“本机验证使用 Python 3.12.9”。

### R-07（P4，工作区整洁）根目录存在空目录 `Memorize/` 与 `.screenshots/`

- **证据**：两目录均无文件，未被 Git 跟踪。
- **影响**：易让验收方误以为存在根级工程；无功能影响。
- **建议**：删除空目录，或在 `.gitignore` 中显式忽略。

## 八、后续决策建议

**结论：先修复 R-01，再执行 macOS 原生测试与真机录屏。**

理由：

1. R-01 是唯一影响可玩性与演示流程的功能缺陷，且修复成本低、影响面局限于 `GameView`；
2. R-03 的原生测试属于环境依赖任务，当前 Windows 环境无法完成，必须先解决代码问题再上机验证，避免“跑完再改”造成证据失效；
3. R-02 与 R-03 可在同一次 macOS 会话中一并完成（生成工程 → 编译 → 跑 132 条 → 录屏）。

建议执行顺序（需用户确认）：

1. **确认补丁**：审阅 `Test/fix/GameView.swift` 与 `.diff`，确认是否合入 `day8`（或带入 `day9`）；
2. **合入与静态验证**：合入后重跑等价回归，确认 132 条不受影响（本次补丁不改 ViewModel，预期无影响）；
3. **macOS 原生验证**：按 README §5.2 执行 `xcodebuild test`，保留日志、截图；
4. **真机录屏**：按 `演示脚本.md` 步骤 1–7 录制，重点补录“超时 → 时间到弹窗 → 再来一局”；
5. **文档收尾**：把原生测试结果与录屏链接补入 README 与答辩大纲，更新遗留状态。

若当前无法获得 macOS 环境：建议先完成 R-02 的工程化准备（在有 macOS 的机器上生成工程）与 R-04/R-06 的文档修订，并将 R-01 补丁作为“待验证补丁”随交付物说明提交，避免超时演示卡死。
