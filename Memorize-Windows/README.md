# Memorize（Windows 版）

原项目是 SwiftUI 编写的 iOS 记忆配对游戏，只能在 macOS + Xcode + iOS 模拟器里运行。
本目录是它的 **Windows 等价移植**：用浏览器技术重写，双击即可在本机运行，
不改变游戏原理、玩法规则与关键参数。

---

## 一、如何运行

**方式一（最简单）**：双击 `index.html`，用 Edge / Chrome 打开即可。

**方式二**：双击 `start.bat`，自动用默认浏览器打开。

**方式三（推荐用于开发）**：在本目录执行

```bash
python -m http.server 8777
```

然后访问 <http://127.0.0.1:8777>。三种方式效果相同，均无需安装任何依赖。

> 不要求联网。所有资源（HTML / CSS / JS / emoji）都在本地。

## 二、玩法

1. 打开后先进入**主界面**：模式（经典 / 闯关）、难度（轻松 / 经典 / 挑战）、
   玩法说明、最高分与「开始游戏」按钮。此时**不计时、不渲染牌面**；
2. 点「开始游戏」（或按 Enter）进入牌局，倒计时**从这一刻**才开始；经典模式默认 **60 秒**，
   每秒递减；
3. 点击卡片翻开，连续翻开两张：
   - 内容相同 → 配对成功，**得分 +2**，两张保持正面且描边变绿、轻弹一下；
   - 内容不同 → 卡片保持正面 **0.8 秒**后自动翻回，期间界面锁定不可点；
   - 若其中任一张在本局中**已经翻看过**，错配时 **得分 −1**；
4. 全部配对完成 → 倒计时**立即停止**，弹出「全部配对成功！」，显示本局得分与最高分；
5. 倒计时归零 → 弹出「时间到！」，显示本局得分；
6. 弹窗可点「再来一局」重开，或点「返回主界面」退出；Esc 关闭弹窗后，提示行会变成
   可点击的重开入口；
7. **暂停**：点提示行右侧的 ⏸ 按钮、点顶部环形倒计时，或按 **P 键**，都会暂停整局：
   计时冻结、翻牌冻结、错配翻回也冻结，牌面上浮出「已暂停」卡片，
   可「继续游戏」或「返回主界面」。**切到别的窗口（页面隐藏）会自动暂停**，回来后不会
   发现时间在背后被走掉；
8. 主题栏可切换 6 个主题（动物 / 运动 / 表情 / 旗帜 / 天气 / 食物），切换即重开一局；
   闯关模式中途换主题等同于重新挑战；
9. 提示行右侧的 ↻ 按钮，或直接按 **R 键**，随时重开本局（牌组重新洗牌、倒计时复位）；
10. 提示行右侧的 ⌂ 按钮，或按 **Esc**，返回主界面：停表并清空本局进度；
11. 顶部副信息实时显示「主题 · 已配对 N/8」，闯关模式还会显示「第 N/3 关」；
12. 主界面的喇叭图标可以开关音效，偏好会记住（配对 / 错配 / 过关 / 结算 / 暂停各有音效）；
    旁边的手机图标开关**震动反馈**（`navigator.vibrate`，桌面浏览器无马达会自动显示为不可用）；
13. **连击加成（仅挑战档）**：连续配对成功时，得分按 **×1 → ×1.25 → ×1.5** 递增
    （第 3 次起封顶 ×1.5）。**任何一次错配立即清零**（哪怕这次并不扣分）；
    暂停、点已配对的卡片、无效点击都**不算**中断。倍率显示在得分区的「连击 ×1.5」上；
14. **长按偷看**：按住一张未翻开的卡片 **0.32 秒**，可以看到图案 **0.4 秒**再自动收回。
    偷看**不翻开卡片、不判定、不计分、不计入「已看过」**，每关次数有限
    （轻松 4 / 经典 3 / 挑战 2，闯关第 1/2/3 关分别 3/2/2），次数显示在提示行左侧；
15. **最近 5 局**：主界面以紧凑横排展示最近 5 局的分数与结局（通关描绿框），
    悬停可看对数与连击；右侧「清空」可一次性清除历史；
16. **助记自适应**：系统会记录「一对牌从第一张被翻看到配上」的用时，
    样本满 8 条后，按平均反应时间**微调错配翻回时长（最多 ±0.15 秒，步长 0.05）**，
    只在**经典模式的轻松 / 经典档**生效，且**只影响下一局**。主界面的说明里可随时「重置」。

### 模式与难度

| 模式 / 难度 | 对数 | 时长 | 错配翻回 | 偷看 | 连击 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 经典 · 轻松 | 6 | 90s | 1.0s | 4 次 | — | 新手熟悉规则 |
| 经典 · 经典 | 8 | 60s | 0.8s | 3 次 | — | **与原版完全一致（默认）** |
| 经典 · 挑战 | 8 | 45s | 0.6s | 2 次 | ×1.25 / ×1.5 | 时间紧、翻回快、连击拉分 |
| 闯关 | 6 → 7 → 8 | 共享 150s | 0.85 → 0.75 → 0.65s | 3/2/2 次 | — | 三关连续，每过一关 **+8s**，时间归零即止步 |

难度只调「时长 / 对数 / 翻回速度 / 偷看次数」这几类**手感参数**，
**计分基数（+2 / −1）在所有模式与难度下完全一致**；连击只是在此之上乘倍率，
且只在挑战档开启（闯关没有难度档，不参与连击，避免两套变量叠加后不可比）。

助记自适应同样是「手感参数微调」，且**只在轻松 / 经典档生效**——挑战档已经有连击，
再叠一层自适应会让难度不可控。

最高分按「模式 + 难度」分别记录：经典三档各记一份，闯关记一份，互不干扰。
记录写在浏览器 `localStorage`；若环境禁用本地存储（隐私模式等），会静默退回到内存记录，
功能照常，只是关掉页面后不保留。


## 五、与原版的已知差异

以下差异均由平台决定，**不影响玩法与规则**：

1. **渲染方式**：SwiftUI 声明式视图 → DOM + CSS。翻牌用 CSS `rotateY` + `perspective`
   （对应原版 `rotation3DEffect(perspective: 0.55)`），环形倒计时用 SVG 描边偏移。
2. **结算弹窗**：原版用系统 `alert`，本版为等价的自定义模态框（同样的标题、正文
   「本局得分：N」与「再来一局」按钮，同样阻塞背景）。
3. **卡片缝隙**：原版 `spacing: 0`，靠圆角与阴影分界。Web 端改用 CSS Grid 的
   `gap`，取值按卡片宽度推导（详见第六节「卡片缝隙」）。**布局算法、卡片尺寸与玩法不变。**
4. **通关后停表**：Swift 原版通关后倒计时会继续走到 0（`gameover` 不调 `stopCountdown`），
   本版按需求改为**通关即停**（`countdownState = 'stopped'`，保留剩余秒数用于「再来一局」）。
   这是唯一一处**有意改变原版行为**的地方，配对判定、计分与其它时序参数均未改动。
5. **国旗 emoji**：Windows 的 Segoe UI Emoji 不渲染区域指示符组合，
   「旗帜」主题会显示为 `CN JP KR` 等国家代码。这是字体限制，
   如需一致可把 `js/model.js` 中该主题的 emoji 换成 Windows 支持的符号。
6. **无原生验证**：本版没有 `xcodebuild` 原生测试结论，行为一致性由
   `tests/run-tests.js` 的 108 条回归用例保证，而非 UI 自动化测试。
7. **界面层增强**（原版没有，属 Web 端补充，**不参与任何规则判定**）：
   起始主界面、卡片悬停上浮 / 按下回弹、锁定期间点击卡片轻微抖动提示、
   结算被 Esc 关闭后提示行变成可点击的重开入口、R 键重开、配对进度显示、
   深色模式、弹窗背景虚化与焦点锁定。详见下一节。
8. **暂停语义统一**：Swift 原版点环形只暂停**倒计时**，牌仍然可以继续翻；
   本版按需求改为**整局暂停**（计时 + 输入 + 错配翻回一起冻结），
   环形与暂停按钮作用相同。原 `pauseCountdown` / `resumeCountdown` 方法保留，
   只是不再作为独立玩法入口。
9. **新增模式 / 难度 / 最高分 / 音效**：属于功能扩展，不改变原版默认档的任何参数与判定。
   切换模式或难度只在主界面生效，对局中调用 `setMode` / `setDifficulty` 会返回 `false`。
10. **连击取整**：×1.25 在基础分 2 上算出 2.5 分，无法直接加整数分。
    本版按「余数结转」处理（2 → 余 0.5 → 下一次 3 分），因此**实时分会最多滞后 1 分**，
    但长期平均严格等于倍率，也不会像四舍五入那样把 ×1.25 与 ×1.5 压成同一个值。
11. **偷看不算「翻看过」**：偷看只改视图，不动 `seenCardIDs`，
    因此「偷看过的牌第一次错配」仍然不扣分。这是刻意的取舍——偷看是有限次数的辅助，
    若要它参与扣分判定，就必须让视图状态反向写回模型，风险大于收益。
12. **自适应只改「下一局」**：一局之内判定节奏恒定，不会打到一半发现手感变了。
    代价是「本局样本」要到下一局才生效。

## 五之二、这次扩展的设计取舍

**为什么暂停要冻结错配翻回**

错配后的 0.8 秒里，那两张牌处于「已翻开、等翻回」的中间态。若只停表不停它，
玩家暂停两秒回来会看到牌面自己翻回去了一次——等于暂停期间游戏逻辑仍在推进。
因此暂停时把这次 `setTimeout` 取消并记下剩余毫秒，恢复时按剩余时间重新排队，
不重置成完整 0.8 秒，保证「暂停多久都不影响判定节奏」。

**为什么闯关共用一条倒计时**

每关各自重置，三关就退化成「连玩三局」，压力不累积，也没有取舍。
共用一条表时，前面拖沓会直接吃掉最后一关的时间，「求快还是求稳」才有意义；
每过一关补 8 秒，既奖励推进，也不至于让慢节奏玩家直接卡死。
补时会同时抬高剩余与总量，环形进度按新总量重算，视觉上会「涨一截」，
玩家能直观看到自己赚到了时间。

**为什么难度只调三个参数**

计分（+2 / −1）与判定顺序是这款游戏的「规则内核」，一旦随难度变化，
最高分之间就不可比，原有回归用例也失去意义。因此难度只动
`{对数, 时长, 翻回速度}` 这类**手感参数**，规则保持一致。

**为什么音效用合成而不是音频文件**

`file://` 直接打开时，音频文件的加载在部分浏览器会被 CORS 策略拦住，
出现「本机能响、拷给别人就哑」。WebAudio 现场合成零体积、零请求、离线可用；
所有播放调用都包在 `try/catch` 里，不支持或上下文被挂起时静默跳过，绝不打断游戏。

## 五之三、第二轮打磨：五项扩展的设计、风险与回退

| 项 | 改动范围 | 关键实现 | 风险与处理 | 回退方式 |
| --- | --- | --- | --- | --- |
| 连击加成 | `config.js`（倍率表）、`viewmodel.js`（计数与发分）、`app.js`（得分区小标题） | 基础分仍由 `Game` 发放（+2 不动），ViewModel 只补「多出来的部分」并计入 `score`；倍率按 1 / 1.25 / 1.5 三档封顶；错配清零 | 分数字段仍是整数（余数结转）；只在挑战档开启，不影响经典档与原版参数 | `Config.COMBO.enabled = false`（同时 `isComboMode` 返回 false，界面自动隐藏倍率与规则文案） |
| 最近 5 局 | `store.js`（`memorize.v2.history` 数组）、`app.js`（渲染）、`index.html`/`style.css`（横排卡片） | 每次结算写入一条，最新在前，上限 20 条，只取前 5 条展示；读出来一律重建字段，脏数据丢弃 | 新增区块会把主界面顶高，已补 `max-height:720/480` 两档压缩；`localStorage` 不可用时退回内存，功能不报错 | 删掉 `KEY_HISTORY` 即可；`clearHistory()` 已在界面上暴露为「清空」 |
| 震动 + 长按偷看 | `viewmodel.js`（`peek()` 状态机）、`app.js`（pointer 事件 + 计时）、`style.css`（偷看视觉）、`config.js`（次数） | 长按 320ms 触发、保持 400ms；`peek()` 只减次数并广播事件，**模型零改动**；偷看后的 `click` 被吞掉 | 触摸松手会补发 `click`，不吞就会「顺手把牌翻开」；暂停/锁定/已翻开/次数用尽都拒绝，并给轻震与 HUD 摇晃；`contextmenu` 已禁用 | 次数设 0 即整体失效；`navigator.vibrate` 不存在时按钮显示为不可用 |
| 深色模式验收 | `style.css`（两份深色变量 + `[data-theme]` 覆盖）、`app.js`（`?theme=` 解析） | 用同一套数值分别服务「系统深色」与「手动指定」，验收时可强制任一屏为深色 | 变量重复两份有漂移风险，已在注释中写明必须同步；对比度问题见《深色模式验收》 | 删掉 `:root[data-theme='dark']` 块即可，系统深色不受影响 |
| 助记自适应 | `config.js`（阈值与增益）、`store.js`（`memorize.v2.timing`）、`viewmodel.js`（采样 + `refreshDelay`）、`app.js`（结算落盘、说明与重置） | 每配对成功产生 1 条样本（不按张记，避免半数为 0 把均值拉低）；偏移量化到 0.05、夹在 ±0.15；只在 `idle` 时改写 | 这是唯一会动核心参数（0.8 秒）的改动，因此设了四道闸：样本≥8、仅在轻松/经典档、仅新开局生效、硬性上下限 | `?adaptive=0` 临时关闭；`ADAPTIVE.enabled=false` 彻底关闭；主界面「重置」清空样本；`effectiveDelay` 在关闭时直接返回原值 |

**连击为什么用「余数结转」而不是四舍五入**

基础分是冻结的 2 分。2 × 1.25 = 2.5、2 × 1.5 = 3，如果对每次单独取整，
前者四舍五入也是 3，两档倍率就变得完全一样，连击的层次感直接消失。
改成「应得分数累计、整数部分入账、小数部分留到下一次」后：
×1.25 的两次得分是 2、3（合计 5，正好等于 2×2.5），×1.5 的每次都是 3。
分数始终是整数，长期平均严格等于倍率，两档也能明显区分。

**自适应为什么按「对」采样而不是按「张」**

一对牌里，第二张是刚刚翻开的，它的「反应时间」天然接近 0。
如果两张都记一条，平均值会被系统性拉低一半，系统就会一直误判「玩家很快」
并不断缩短翻回时间，最终把难度推到上限。改为每对只记一条
（从这一对里**第一张**被翻看到配对完成），平均值才反映真实的回忆耗时。

## 六、界面与交互细节

这一节记录界面层的取舍，便于后续调整时知道「为什么这么做」。

**布局**

| 处理 | 原因 |
| --- | --- |
| 卡片区垂直居中 | 原先贴顶，窗口偏高时下半屏空着，卡组显得被挤在上半部 |
| 得分浮标移到数字下方 | 得分区在最右侧，向左飘会正好压在环形倒计时上（两者相距不到 60px） |
| 提示行改用 `min-height` | 原先写死 18px，窄屏长文案换行会被裁掉 |
| 卡片区兜底 `min-height: 420px` | 窗口极矮时页面改为滚动，而不是把卡片压到看不清 |
| emoji 字号上限 36 → 52px | 121px 宽的卡片上 36px 只占三成，图形显得小而空 |

**交互**

| 处理 | 原因 |
| --- | --- |
| `animation-fill-mode: both` → `backwards` | `both` 会在发牌动画结束后保留 `transform: none`，而 CSS 动画优先级高于普通声明，会压住 `:hover` / `:active` 的位移，导致悬停完全没反应 |
| 锁定期间点击卡片抖动 | 模型层会直接忽略这类点击，若界面也无反馈，玩家会误判为卡死 |
| 环形加 hover 提示气泡 | 环是暂停开关，但界面上没有任何说明，只有「点到才发现」 |
| 结算 Esc 关闭后，提示行变可点击 | 原先 Esc 只隐藏弹窗，游戏仍处于 finished + 锁定，主题栏也被锁，除了刷新页面没有重开入口 |
| 弹窗 Tab 焦点锁定 | 弹窗内只有一个按钮，不锁定会让焦点跑回背后的棋盘 |
| 重开按钮 + R 键 | 原先想换一副牌只能切主题，等于被迫换主题 |

**起始主界面与计时边界**

主界面（`#home`）与游戏界面（`#game`）是同一容器下的两个互斥视图，只做
`hidden` 切换，没有路由。计时边界由三处保证：

| 时机 | 动作 | 结果 |
| --- | --- | --- |
| 页面加载 | 只渲染主界面与静态信息，不建棋盘、不调计时接口 | `countdownState = 'idle'`，剩余 0 秒，`board` 子节点为 0 |
| 点「开始游戏」 | `viewModel.startGame()`：重洗牌组 → 建棋盘 → `startCountdown(60)` | 唯一启动计时的入口 |
| 通关 | `_haltCountdownOnWin()` 停掉 interval，状态置 `stopped` | 剩余秒数冻结，弹窗显示期间不再递减 |
| 返回主界面 | `viewModel.leaveGame()` 停表、解锁、清空剩余 | 回到 `idle`，主界面不会继续走秒 |

`startCountdownIfNeeded()` 仍然保留（对齐原版 `onAppear` 的方法面），但页面启动时
**不再调用**它 —— 这正是「进入游戏前不计时」的关键。

**暂停的状态边界**

暂停涉及四个开关，任何一处漏掉都会出现「看着暂停了，其实还在走」：

| 对象 | 暂停时 | 恢复时 |
| --- | --- | --- |
| 倒计时 | `clearInterval`，状态置 `paused`，剩余秒数保留 | 重新 `setInterval`，从剩余秒数继续 |
| 错配翻回 | `clearTimeout`，记下「还剩多少毫秒」并作废令牌 | 按剩余毫秒重新排队，不重置成完整 0.8s |
| 输入 | 模型 `choose()` 直接返回；遮罩盖住棋盘；`board.inert` 移出焦点序列 | 解除锁与 `inert` |
| 视图状态 | 遮罩 + 提示行「已暂停 · 计时与翻牌已冻结」+ 图标换成播放三角 | 遮罩收起，焦点回到暂停按钮 |

边界条件：

- 主界面（`idle`）与已结算（`finished` / `stopped`）一律不接受暂停，`pause()` 返回 `false`；
- 重复暂停 / 重复恢复都只发一次 `pause` / `resume` 事件，视图不会重复处理；
- 暂停中按 Esc 直接回主界面，`leaveGame()` 会顺手清掉暂停态，不会留下半暂停界面；
- 页面隐藏（切窗口、切标签页）自动暂停，避免后台走表。

**闯关的关卡切换**

清空当前关时不再直接结算，而是先判断「是否还有下一关」：

```
本关清空
├─ 闯关且 levelIndex + 1 < 3 → _carryScore += 本关得分
│                             换下一关牌组（6 → 7 → 8 对）
│                             倒计时 +8s（不重置）
│                             发 levelclear 事件 → 重建棋盘 + 气泡提示「第 N 关 · 时间 +8 秒」
└─ 否则 → resultReason = 'win'，停表，弹结算
```

补时不会修改「本局初始时长」，所以「重新挑战」永远从 150 秒开始，而不是从累计后的大数字开始。
超时在任何一关都会直接结束整局，结算文案变成「挑战失败 · 止步第 N 关」。

**卡片缝隙**

不用「固定 2px 内缩」，改为 CSS Grid `gap` + 按卡片宽度推导，原因有三：

1. 内缩 2px 是**每边** 2px，相邻两张之间实际是 4px，与「2px 缝隙」的说法不符；
2. 固定值在小卡（手机 5 列时约 64px）上占 3%，在大卡上几乎看不见，同屏疏密不一致；
3. 内缩让卡面比布局单元格小一圈，2:3 宽高比与圆角比例都会轻微失真。

最终生效的取值逻辑（`js/layout.js` + `js/app.js`）：

```
① 先按「无缝」估算卡片基准宽度 base = itemWidthThatFits(count, W, H, 2/3)
② gap = round(clamp(base × 3.2%, 3, 10))        // 整数像素
③ 带 gap 重算一次：itemWidth = itemWidthThatFits(count, W, H, 2/3, gap)
   —— 内部按 (W - (列数-1)×gap) / 列数 计算，并按
      rowCount×高 + (rowCount-1)×gap ≤ H 逐列试探
④ cols = floor((W + gap) / (itemWidth + gap))
⑤ 余量 = W - (cols×itemWidth + (cols-1)×gap)，恒有 0 ≤ 余量 < cols，
   由 grid 的 justify-content: center 均分到两侧
```

实测结果（同一套代码，只改视口）：

| 视口 | 列 × 卡宽 × 高 | 缝隙 | 总宽 / 棋盘 | 总高 / 棋盘 |
| --- | --- | --- | --- | --- |
| 900×760 | 6 × 118 × 177 | 4px | 728 / 728（正好填满） | 539 / 587 |
| 390×844 | 4 × 89 × 134 | 3px | 365 / 366 | 545 / 682 |
| 360×640 | 5 × 64 × 96 | 3px | 332 / 336 | 393 / 478 |

三组都满足：不溢出、不重叠、相邻卡片实测间距等于 `gap`、横纵缝隙一致。
取整带来的 1–4px 余量由居中吸收，视觉上等价于均匀留白；之所以不改成
小数宽度去「精确填满」，是因为整数像素在 3D 翻转时不会出现半像素发虚。

**深色模式**

用 `prefers-color-scheme` 换一组变量值，不另写一套选择器 —— 对应 SwiftUI
语义色随系统外观自动切换的行为。`<meta name="color-scheme" content="light dark">`
同时让滚动条等原生控件跟随。

**调试探针**

URL 追加 `?probe=1` 会把当前界面、模式、难度、关卡、牌数、棋盘节点数、列数、卡宽、缝隙、
面板尺寸、卡片实测矩形、圆角、得分、剩余秒数、暂停标记、配对进度、最高分写进页面标题。
用于在没有截图能力的环境里核对布局，正常访问不触发。

## 八、后续可以怎么扩展

- **改难度 / 加档位**：`js/config.js` 的 `DIFFICULTIES`，一档只需 `{id, name, duration, pairs, mismatchFlipDelay}`；
- **改闯关节奏**：同文件的 `CAMPAIGN`（`timeBudget` 初始秒数、`clearBonus` 每关补时、`stages` 各关对数与翻回速度）；
- **改主题**：`js/model.js` 里 `Theme.builtIn` 的 `numberOfPairs` 控制对数，
  或加新主题（`emojis` 至少 1 个，对数会自动截断到 emoji 数量）；
- **改翻牌 / 发牌节奏**：动画时长在 `css/style.css`（搜索 `0.45s` / `0.35s` / `0.06`）；
- **换音色**：`js/audio.js` 的 `NOTE` 与 `play()` 里的音符序列，纯合成，不需要素材文件；
- **排行榜**：`js/store.js` 现在只存单机最高分，接后端时把 `getBest` / `submit` 换成接口即可，
  调用方（`app.js`）不用改；
- **打包成桌面程序**：本目录本身就是一个静态站点，可直接用 Electron / Tauri 套壳，
  也可部署到任意静态托管。
