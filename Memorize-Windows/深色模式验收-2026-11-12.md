# 深色模式验收记录（2026-11-12）

本文记录第二轮打磨中「深色模式逐屏核对」的**实际做法、发现的问题与修复结果**，
以及**仍然需要真机确认的项**。

> 结论先说：本轮在浏览器里把深色模式逐屏量化核对了 **9 个界面 × 5 个视口**，
> 修掉 6 个真实缺陷（3 个对比度不达标、1 个文字几乎不可见、1 个深色边界丢失、
> 1 个新增区块导致的 2px 滚动）。但**没有在真实 iOS / macOS 设备的系统深色下逐屏看过**，
> 这一项仍是未完成状态，清单见文末第四节。

---

## 一、验收方法与边界

| 项 | 做法 |
| --- | --- |
| 触发深色 | URL 加 `?theme=dark`（`app.js` 解析后给 `<html>` 打 `data-theme`），不必改系统设置 |
| 覆盖界面 | 主界面（含 5 条历史 + 自适应说明）、经典牌局、偷看态、连击态、暂停层、结算弹窗、闯关牌局 |
| 覆盖视口 | 1440×880、1024×700、390×844、360×640、320×568（另加 844×390 / 667×375 / 480×360 横屏） |
| 布局检查 | `scrollHeight/clientHeight`、横向溢出、顶栏三段是否重叠、卡片是否全在视口、提示行与左右按钮是否互相压盖、副信息是否被裁切、历史卡片是否溢出 |
| 颜色检查 | 读取每个文字节点的 `color` 与其**实际合成背景**，按 WCAG 相对亮度算对比度；正文阈值 4.5:1，大字号/标题 3:1 |
| 判定方式 | 同一段脚本在 iframe 里运行同一份代码，只改视口与配色，结果导出为 JSON 后统计 |

**边界（重要）**：这是 Chromium 内核下的**深色模式模拟**，不是真机。
它能发现配色、层叠、布局层面的问题，但发现不了 OLED 拖影、系统辅助功能的强制反色、
iOS 安全区、字体回退等只在真机上出现的问题。

## 三、发现并修复的问题

| # | 问题 | 发现方式 | 修复 | 修前 → 修后 |
| --- | --- | --- | --- | --- |
| 1 | 次要文字对比度不足（副标题、规则、副信息、提示行、得分标题、历史标签全用它） | 浅色下测得 **2.92:1** | `--secondary-label` 由 `#8e8e93` 加深为 `#6a6a70` | 2.92 → **4.82** |
| 2 | 开始按钮白字压在 `#007aff` 上偏浅 | 测得 **4.02:1** | 新增 `--accent-strong: #0068d9` 专供「需要白字压在上面」的按钮 | 4.02 → **5.27** |
| 3 | 选中的难度芯片：蓝字压 12% 蓝底 | 测得 **3.6:1** | 文字改回主文字色，选中态由蓝框 + 蓝底表达 | 3.6 → **15.25** |
| 4 | 「最近 5 局」里通关那格的分数用亮绿 | 测得 **1.99:1**，几乎看不清 | 分数统一用主文字色，胜负改用绿色**描边**表达 | 1.99 → **15.25** |
| 5 | 深色下卡片 `#1c1c1e` 与纯黑背景几乎没有边界 | 逐屏核对时肉眼即可见「卡组糊成一片」 | 新增 `--card-edge`（浅色透明、深色 9% 白），作为卡片第 1 层阴影 | 边界由 0 → 1px |
| 6 | 深色下芯片/徽标底色 12% 白过淡（历史卡片、偷看徽标、自适应说明几乎看不出是「一块」） | 逐屏核对 | `--chip-bg` 在深色下提到 24% 白 | 视觉可辨 |
| 7 | 新增「最近 5 局」后，700px 以下窗口主界面多出 2px 滚动条 | 布局检查 `scrollHeight 570 / clientHeight 568` | 补 `max-height: 720px` 与 `480px` 两档压缩；主界面容器改用 `:has` 区分「按内容撑高 / 按视口锁高」 | 570 → 568，五档视口全部 `scroll=N` |

补充说明：第 1、2、3、4 项在**浅色模式下同样存在**（并非深色特有），
只是本轮为了做统一核对才一起测出来并修掉；深色下这几处的绝对值更高（7.33 / 5.27），
达标但偏紧，改动后两边都留出了余量。

**已知且不打算改的一处**：主界面大标题是渐变文字（`background-clip: text` +
`color: transparent`），无法用前景色算对比度，脚本里标为「未统计」。
它在浅色下是蓝→青渐变、深色下保持同一个蓝，实测肉眼可读；
若将来要求严格合规，需改成纯色文字。

## 四、仍然需要真机确认的项（未完成）

以下必须在真实设备上、系统切到深色后逐屏看，模拟环境给不出结论：

1. **iOS Safari 系统深色**：`prefers-color-scheme` 生效时配色是否与 `?theme=dark` 完全一致；
   `theme-color` meta（地址栏配色）是否跟随。
2. **OLED 纯黑**：`#000000` 背景在暗房间里滚动卡片是否出现拖影/黑阶断层；
   若明显，可把 `--bg` 改成 `#0a0a0c`（非纯黑）缓和，需要真机确认再改。
3. **深色下的 emoji 观感**：彩色 emoji 压在 `#1c1c1e` 卡片上是否过亮刺眼；
   必要时给 `.card-front` 加一层极淡的暖色底。
4. **系统辅助功能**：
   - 「增强对比度」（iOS）会改变系统色，需确认次要文字仍可读；
   - 「降低透明度」会去掉遮罩半透明，需确认暂停层/结算层的层级仍清楚；
   - Android Chrome 的「强制深色」（force dark）可能二次反色，需确认不会把卡片反成亮色。
5. **iOS 安全区/刘海**：横屏时 `viewport-fit=cover` 与 `env(safe-area-inset-*)` 尚未适配，
   需确认开始按钮不被手势条遮挡。
6. **深色 + 震动/长按**：真机上长按 0.4 秒的偷看是否被系统长按手势（文字选择、3D Touch 替代）
   抢走；本轮只在 Chromium 用 `pointerdown/up` 模拟验证过。
7. **深色 + 视口 320×568 实机**（iPhone SE 一代等）：本轮是 iframe 模拟，字体渲染略有差异，
   需确认「最近 5 局」五格仍不折行。

## 五、如何复现本轮核对

1. 用任意静态服务器托管 `Memorize/`（`file://` 也能跑，但用服务器更方便加参数）；
2. 打开 `index.html?theme=dark`，逐屏切换：主界面 → 开始 → 长按偷看 → 配对触发连击 →
   P 暂停 → 通关看结算 → 返回主界面看「最近 5 局」；
3. 想复现「最挤状态」：先在控制台执行
   `localStorage.setItem('memorize.v2.history', JSON.stringify(Array.from({length:6},(_,i)=>({mode:'classic',difficulty:'hard',score:20-i*4,reason:i%2?'timeout':'win',pairs:8,matched:6,combo:4,at:Date.now()}))));`
   再刷新，主界面就会带上 5 条历史；
   追加 `memorize.v2.timing`（12 条大于 2600 的数值）可让自适应说明出现；
4. 把窗口拉到 320×568，确认无纵向滚动条、开始按钮完整可见。
