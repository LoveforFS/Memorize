## 一、项目概述

### 1.1 项目定位

Memorize 是一款基于 SwiftUI 的单机记忆配对游戏。玩家点击卡片翻开 emoji，找出全部对子；
在 60 秒倒计时结束前完成配对即通关，超时则本局结束。项目以 Stanford CS193p 的 Memorize
为原型，按 M2–M8 模块逐日迭代，最终形成模型、视图模型、视图三层结构。

### 1.2 技术栈

| 项目 | 选型 |
| --- | --- |
| 语言 | Swift 5.9 工具链（工程语言模式 `SWIFT_VERSION = 5.0`） |
| UI 框架 | SwiftUI |
| 状态与响应式 | Combine（`ObservableObject` / `@Published` / `@StateObject`） |
| 测试框架 | XCTest（单元 / 集成）、XCUITest（UI 自动化） |

| 辅助验证 | Python 3 `unittest` 行为等价执行器（仅 Windows 阶段使用） |

## 二、整体架构

### 2.1 分层与依赖方向

```
┌─────────────────────────────────────────────────────────────┐
│ 表现层 Views（SwiftUI）                                      │
│ GameView / CardView / Cardify / Pie / ThemeButton /          │
│ AspectVGrid / AnimationTiming                                │
└───────────────────────────┬─────────────────────────────────┘
                            │ 只读 @Published，只调用 ViewModel 方法
┌───────────────────────────▼─────────────────────────────────┐
│ 视图模型层 ViewModels                                        │
│ GameViewModel / MismatchTimerScheduling /                    │
│ GameAnimationCoordinator / CountdownClock                    │
└───────────────────────────┬─────────────────────────────────┘
                            │ 读写模型，不反向依赖视图
┌───────────────────────────▼─────────────────────────────────┐
│ 模型层 Models（纯 Swift）                                     │
│ Theme / Card / Game                                          │
└─────────────────────────────────────────────────────────────┘

测试层 MemorizeTests / MemorizeUITests ──▶ 依赖全部业务层 + XCTest
等价执行层 WinTestHarness ──▶ 以 Python 镜像业务逻辑，不参与应用运行
```

| 层级 | 职责 | 允许依赖 | 禁止事项 |
| --- | --- | --- | --- |
| Model | 主题校验、牌组生成、翻牌 / 配对 / 计分规则 | Foundation、SwiftUI（仅 `Color`） | 不持有计时器、不发布 UI 状态、不引用视图 |
| ViewModel | 唯一状态源；同步模型到 `@Published`；调度翻回与倒计时；动画边界判定 | Model、Foundation、Combine | 不绘制界面、不依赖具体视图类型 |
| View | 渲染与手势；把用户操作转成 ViewModel 调用 | ViewModel、SwiftUI | 不写业务规则、不直接修改模型 |
| Test | 逐条验证模型 / 视图模型 / 纯函数几何 / UI 流程 | 全部业务层、XCTest | 不复制实现、不依赖真实等待 |
| Harness | Windows 下的行为等价断言与用例映射校验 | Python 标准库 | 不替代 macOS 原生结论 |

### 2.2 数据流

**翻牌链路**

```
用户点击卡片
  → GameView.choose(_:)
  → withAnimation(AnimationTiming.flip)
  → GameViewModel.choose(_:)
  → Game.choose(_:)（翻面 / 配对 / 计分 / 错配登记）
  → GameViewModel.syncFromGame()
  → @Published cards / score / scoreRevision / scoreChangeDelta
  → CardView + Cardify 重绘；得分区跳动；DealtCardView 发牌
```

**错配链路**

```
Game.choose → hasPendingMismatch == true
  → ViewModel 锁定 isInteractionLocked
  → MismatchTimerScheduling.schedule(after: 0.8)
  → completeMismatchFlipBack()
  → Game.flipBackMismatch() → syncFromGame()
  → 解锁（除非已超时）
```

**倒计时链路**

```
GameView.onAppear → startCountdownIfNeeded()（幂等）
  → CountdownClock.start(interval: 1)
  → tickCountdown() 每秒递减 countdownRemaining
  → Pie 渲染进度；remaining ≤ 5 转红
  → 归零：finishCountdown() → didTimeOut = true、锁定交互、弹结算窗
  → 点击“再来一局” → newGame() → 按原时长重启倒计时
```

### 2.3 状态与交互规则

| 状态 | 触发 | 表现 | 退出条件 |
| --- | --- | --- | --- |
| 正常可交互 | 初始 / 翻回完成 | 卡片、主题、计时均可操作 | 翻开第二张错配 |
| 错配锁定 | 两张内容不同 | 提示“配对失败，卡片即将翻回…”；0.8 秒后自动翻回 | 翻回完成 |
| 通关 | 所有卡片 `isMatched` | 弹窗“全部配对成功！”+ 本局得分 | 点击“再来一局” |
| 超时 | `countdownRemaining == 0` | 环归零、数字转红、弹窗“时间到！”+ 本局得分；交互锁保持 | 点击“再来一局” |
| 暂停 | 点击环形倒计时 | 提示“倒计时已暂停…” | 再次点击环形 |
| 未开始 | 倒计时尚未启动 | 环形半透明、显示 0 | `startCountdown` |

结算弹窗由 `isGameOver` 与 `didTimeOut` 共同驱动，标题优先取通关文案；
按钮统一为“再来一局”，行动统一为 `viewModel.newGame()`。

## 三、核心代码模块说明

### 3.1 入口层

#### MemorizeApp.swift

- **职责**：`@main` 应用入口，创建 `WindowGroup` 并装载 `GameView`。
- **测试开关**：启动参数包含 `-uitesting` 时，注入“2 对、不洗牌”的确定性牌局，
  保证 UI 自动化测试的卡片下标与内容稳定。
- **关键接口**：`MemorizeApp.body`、`isUITesting`。
- **边界**：仅做依赖装配，不含任何游戏规则。

### 3.2 模型层（Models）

#### Theme.swift

- **职责**：描述一套主题（名称、emoji 集合、主题色、对数），并在创建时完成校验。
- **校验规则**：
  1. 名称去除首尾空白后不能为空 → `ValidationError.emptyName`；
  2. emoji 集合清理空白项后至少一个 → `emptyEmojiSet`；
  3. 对数必须大于 0 → `invalidNumberOfPairs`；
  4. 对数超过 emoji 数量时按可用数量截断（`min`），不抛错。
- **内置主题**：动物、运动、表情、旗帜、天气、食物，各 8 个 emoji、默认 8 对。
- **边界**：`try!` 仅用于常量内置主题；外部创建必须处理 `throws`。

#### Card.swift

- **职责**：单张卡片的状态载体。
- **字段**：`id`（唯一）、`content`（emoji，创建时去空白且 `precondition` 非空）、
  `isFaceUp`、`isMatched`。
- **判等**：只比较 `id`，翻面 / 配对状态不参与 `==`，避免集合与查找因状态变化而失配。
- **边界**：内容为空属于调用方违约，用 `precondition` 在 Debug 阶段快速失败。

#### Game.swift

- **职责**：牌局唯一状态源，维护卡片数组、得分、待翻回卡片、已见卡片集合。
- **核心规则**：
  - 每个 emoji 生成两张卡片，`numberOfPairs` 被 `clamp` 到 `1...emojis.count`；
  - 已配对或已翻开的卡片再次点击直接忽略；
  - 翻开第二张时立即判定：内容相同 → 双方 `isMatched`、`score += 2`；
  - 内容不同 → 两张保持正面并记录到 `mismatchedCardIDs`，等待外部延时翻回；
  - 若错配涉及“本局已翻看过”的卡片 → `score -= 1`；
  - `isGameOver = 非空 && 全部 isMatched`；`matchedPairsCount = 已配对卡片数 / 2`。
- **关键接口**：`init(theme:numberOfPairs:shuffle:)`、`choose(_:)`、`flipBackMismatch()`、
  `newGame(shuffle:)`、`startNewGame(with:shuffle:)`、`makeDeck(emojis:numberOfPairs:shuffle:)`。
- **边界**：对数为 0 或负数会被 `clamp` 到 1；超过 emoji 数会截断；空牌组不会判定通关。

### 3.3 视图模型层（ViewModels）

#### GameViewModel.swift

- **职责**：视图与模型之间的唯一通道；发布 UI 状态；调度错配翻回与倒计时。
- **发布属性**：
  - `cards`、`score`：大纲约定的核心接口；
  - `isInteractionLocked`：错配 / 超时期间锁定交互；
  - `boardRevision`：重开或切题时递增，驱动错峰发牌；
  - `scoreRevision`、`scoreChangeDelta`：得分真正变化时更新，驱动数值动画；
  - `countdownRemaining`、`countdownTotal`、`countdownState`、`didTimeOut`。
- **关键方法**：`choose(_:)`、`endFlip(for:)`、`newGame()`、`chooseTheme(_:)`、
  `startCountdown(duration:)`、`startCountdownIfNeeded()`、`tickCountdown()`、
  `pauseCountdown()`、`resumeCountdown()`、`toggleCountdown()`、`stopCountdown()`、
  `completeMismatchFlipBack()`。
- **调度与令牌**：每次错配生成 `pendingTimerToken`；重开 / 切题会置空令牌，
  使旧的延时回调失效，避免“旧任务翻回新牌局”。
- **超时锁**：`finishCountdown()` 设置 `didTimeOut`、`countdownState = .finished` 并锁定；
  `completeMismatchFlipBack()` 结束时按 `countdownState == .finished` 决定是否解锁，
  确保超时锁不会被翻回任务意外解除。
- **倒计时重启**：`newGame` / `chooseTheme` 仅在 `countdownDuration > 0` 时按原时长重启；
  初始进入不自动启动，必须由 `startCountdownIfNeeded()` 或测试显式启动。
- **边界**：`startCountdown(duration:)` 对非正数直接返回；暂停期间 tick 不减秒；
  已结束状态忽略 `toggleCountdown`。

#### MismatchTimerScheduling.swift

- **职责**：把“延时”抽象为协议，便于测试注入。
- **接口**：`schedule(after:action:)`。
- **生产实现**：`DispatchMismatchTimer` 使用 `DispatchQueue.main.asyncAfter`。
- **边界**：协议只负责一次性调度，不负责取消；取消语义由 ViewModel 的令牌实现。

#### GameAnimationCoordinator.swift

- **职责**：动画边界控制器，集中判定“哪些变化可以播放动画”。
- **规则**：
  - `beginFlip(for:)` 对同一卡片去重，动画结束前重复点击返回 `false`；
  - `scoreDidChange(from:to:)` 仅在数值真正变化时递增 `scoreRevision`；
  - `beginNewBoard()` 清空进行中的翻牌并递增 `boardRevision`。
- **接口**：`beginNewBoard`、`beginFlip`、`endFlip`、`endAllFlips`、`scoreDidChange`、
  `activeFlipCount`。

#### CountdownClock.swift

- **职责**：倒计时状态、默认参数与周期计时器抽象。
- **类型**：`CountdownState`（idle / running / paused / finished）、
  `CountdownDefaults`（`duration = 60`、`tickInterval = 1`）、
  `CountdownClock` 协议、`DispatchCountdownClock` 实现（`Timer.scheduledTimer`）。
- **边界**：`start` 重复调用会先 `stop` 旧计时；`deinit` 会失效计时器，避免泄漏。

### 3.4 视图层（Views）

#### GameView.swift

- **职责**：主界面组装与交互入口。
- **结构**：`header`（标题 / 主题名 / 环形倒计时 / 得分）→ `themeBar` → `interactionHint`
  → `cardArea`。
- **关键行为**：
  - `.onAppear` 调用 `startCountdownIfNeeded()`；
  - `.onChange(of: scoreRevision)` 触发得分反馈（缩放 + 浮标）；
  - `.onChange(of: isGameOver)` 与 `.onChange(of: didTimeOut)` 打开结算弹窗；
  - `resultAlertTitle` 优先“全部配对成功！”，否则“时间到！”；
  - 弹窗唯一按钮“再来一局”调用 `newGame()`；
  - `choose(_:)` 在 `withAnimation` 中调用 ViewModel，并在 0.45 秒后 `endFlip`；
  - 错配/超时锁定期间，主题栏禁用、卡片手势由 ViewModel 前置拦截。
- **可访问性标识**：`scoreLabel`、`scoreDeltaLabel`、`themeNameLabel`、
  `interactionHint`、`theme-<名称>`、`card-<下标>`、`countdownPie`。

#### CardView.swift

- **职责**：单卡渲染与 3D 翻牌。
- **实现**：背面问号层先旋转 180° 抵消镜像；整体按 `isFaceUp` 旋转 0° / 180°，
  `perspective: 0.55`；`.animation(AnimationTiming.flip, value: isFaceUp)`。
- **可访问性**：标签为“未翻开的卡片”“已翻开的卡片 <emoji>”“已配对的卡片 <emoji>”。
- **边界**：已配对卡片即使 `isFaceUp == false` 也强制显示正面。

#### Cardify.swift

- **职责**：统一卡片外观规范与修饰器，所有卡片外观的唯一入口。
- **CardStyle 纯函数**（以短边为基准）：
  | 属性 | 比例 | 上下限 |
  | --- | --- | --- |
  | 宽高比 | 2 / 3 | 固定 |
  | 圆角 | 12% | 6…20 pt |
  | 描边 | 1% | 1…3 pt |
  | 内边距 | 8% | 2…8 pt |
  | 阴影半径 | 3% | 1…6 pt |
- **颜色**：正面 `systemBackground`，背面 `accentColor`，普通描边 `accentColor`，
  配对描边 `green`，阴影黑色 12%。
- **边界**：尺寸非正时几何量返回 0；`.aspectRatio(2/3, .fit)` 保证任意容器不拉伸。

#### Pie.swift

- **职责**：环形倒计时视图与几何计算。
- **PieGeometry**：
  - `progress = remaining / total`，裁剪到 0…1；`total <= 0` 返回 0；
  - `startAngle = -90°`（12 点方向），`endAngle = -90° + 360° × progress`；
  - 环宽 = 直径的 10%，限制 3…10 pt。
- **Pie**：灰色轨道 + 按进度 `trim` 的彩色圆弧 + 中心秒数；`remaining ≤ 5` 且 `total > 0` 转红；
  进度变化使用线性动画，时长等于 tick 间隔。
- **可访问性**：标签“倒计时 N 秒”，标识 `countdownPie`。

#### AspectVGrid.swift

- **职责**：自适应网格容器。
- **算法**：`itemWidthThatFits` 从 1 列开始递增，直到“行数 × 单元高度”不超过可用高度；
  宽度向下取整避免像素溢出；全部放不下时按宽高两个方向压缩取更小值。
- **边界**：数量 / 宽 / 高 / 比例任一非正返回 0。

#### ThemeButton.swift

- **职责**：主题选择按钮；展示前两个 emoji 与名称；选中态用主题色填充与描边。
- **可访问性**：标签“主题：<名称>”，值“当前已选中”。

#### AnimationTiming.swift

- **职责**：动画参数与节奏策略的唯一来源，视图不硬编码时长。
- **参数**：

  | 常量 | 值 | 用途 |
  | --- | --- | --- |
  | `flipDuration` | 0.45 s | 3D 翻牌 |
  | `dealDuration` | 0.35 s | 单卡发牌 |
  | `dealStagger` | 0.06 s | 相邻卡片错峰 |
  | `dealMaxStagger` | 0.6 s | 发牌延迟上限 |
  | `scorePopDuration` | 0.3 s | 得分弹跳响应 |
  | `scorePopScale` | 1.25 | 得分缩放峰值 |
  | `scoreDeltaVisibleDuration` | 0.7 s | `+2` / `-1` 浮标可见时长 |

- **曲线**：翻牌 `easeInOut`；发牌 `easeOut`；得分 `spring(response: 0.3, damping: 0.62)`；
  复位 `easeOut(0.18)`。
- **函数**：`dealDelay(forCardAt:)` 线性错峰并封顶；`scoreDelta(from:to:)` 计算差值。

### 5.2 测试与验证类

## 六、功能边界

### 6.1 已实现能力

- 6 套内置主题，支持运行中切换并重置牌局；
- 每局 8 对（可由 `numberOfPairs` 调整，范围 1…emoji 数量）；
- 翻牌、配对、重复错配扣分、通关判定；
- 错配 0.8 秒自动翻回，期间锁定交互；
- 60 秒环形倒计时，支持暂停 / 继续；
- 最后 5 秒视觉警示，超时锁定并弹出结算窗；
- 通关与超时共用结算弹窗，“再来一局”可恢复；
- 3D 翻牌、错峰发牌、得分跳动与浮标；
- 统一卡片外观（圆角 / 描边 / 内边距 / 阴影 / 宽高比）；
- 自适应网格，任意尺寸不溢出；
- 完整可访问性标签与 UI 测试标识。

### 6.2 明确不支持 / 未覆盖

| 边界 | 现状 | 影响 |
| --- | --- | --- |
| 多指同时点击多张卡片 | 未处理 | 极端快速操作可能由 ViewModel 锁与模型守卫兜底，但非正式支持 |
| 应用退到后台 | 倒计时不感知前后台 | 后台期间计时可能不准 |
| 游戏进度持久化 | 不支持 | 杀掉进程后得分与牌局丢失 |
| 自定义主题 | 不支持 | 仅 6 套内置主题 |
| 无障碍动态字体 / VoiceOver 完整流程 | 仅提供标签 | 未做完整朗读顺序优化 |
| 深色模式专项适配 | 使用系统语义色，自动适配 | 未做逐主题对比度校验 |
| 横竖屏切换动画 | 布局自适应，无专项过渡 | 切换瞬间可能重排 |
| iPad 多任务 / 分屏 | 未专项验证 | 依赖 `AspectVGrid` 自适应能力 |

### 6.3 输入与状态边界

- 主题对数 ≤ 0：`Theme` 初始化抛错；`Game` 内部 `clamp` 到 1。
- 卡片内容为空：`Card` 初始化 `precondition` 失败（属于调用方违约）。
- 倒计时时长 ≤ 0：`startCountdown` 直接忽略。
- 暂停期间 tick：`tickCountdown` 状态守卫，不减秒。
- 超时后错配翻回任务到达：保持锁定。
- 重开 / 切题后旧回调到达：令牌失效。
- 空牌组：不判定通关，界面显示空态。
